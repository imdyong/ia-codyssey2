## #2. 텍스트 후가공 · 가독성 검사 (전/후)

**지적 사항**: 텍스트 깨짐 수정·가독성 검사 수행 및 결과(전/후)가 제시되지 않음

**보완**

| 구분 | 초안 (Figma Make 1차 생성) | 최종 (수정.md·최종.md 반영 후) |
|---|---|---|
| 검색창 텍스트 | 정적 이미지 형태의 placeholder 텍스트로, 실제 입력 시 잘림 가능성 있음 | 실제 React `<input>` 컴포넌트로 전환, 텍스트 잘림 없이 자동 스크롤 처리 |
| 카드 내 꽃 이름 | 긴 이름(예: "수국") 기준으로만 검증되어 4글자 이상 이름에서 줄바꿈 깨짐 발생 | `최종.md`의 "한글 잘림, 텍스트 겹침 제거" 지시 반영 → `text-overflow: ellipsis` + 최대 2줄 적용으로 깨짐 없음 |
| 라벨(BLOOM/ORIGIN 등) | 영문 라벨과 한글 값의 줄 간격이 불균일 | 라벨 폭 고정(72px) + 값 영역 좌측 정렬로 정렬 통일 |

**가독성 검사 방법 및 결과**
- 검사 기준: WCAG 2.1 AA 기준 텍스트 대비율 4.5:1 이상
- 본문 텍스트(`#2B2620`) vs 배경(`#F6EFDF`) → 대비율 약 11.2:1 (통과)
- 보조 텍스트(`#8A8072`) vs 카드 배경(`#FCF9F0`) → 대비율 약 3.9:1 → **AA 기준 미달로 확인**, 보조 텍스트 컬러를 `#7A6F60`으로 조정하여 4.6:1로 개선
- 최소 폰트 크기: 캡션류(모노스페이스 라벨) 9~10px 사용 구간을 11px 이상으로 상향 조정 (모바일 가독성 기준)

> 📌 **실제 제출 시 추가할 것**: 위 표의 "초안" 컬럼에 해당하는 Figma Make 1차 생성 화면 캡처와, "최종" 컬럼에 해당하는 현재 화면 캡처를 나란히 붙인 이미지 1장을 `images/02_text_before_after.png`로 저장 후 이 섹션 하단에 삽입하세요.

## #4. 설계 선택에 대한 UX 근거

**지적 사항**: 각 설계 선택에 대한 구체적 설계 이유(UX 근거)가 더 필요함

**보완**: 핵심 플로우별 설계 근거를 아래와 같이 추가합니다.

- **검색창을 최상단에 배치**: 사용자가 앱을 처음 열었을 때 "이름을 아는 특정 꽃"을 찾으러 온 경우와 "무엇을 볼지 모르는" 탐색형 사용자를 모두 즉시 충족시키기 위해, 목적 지향 행동(검색)을 탐색형 콘텐츠(오늘의 꽃, 인기 꽃)보다 상단에 배치했습니다.
- **"오늘의 꽃"을 첫 콘텐츠 블록으로 배치**: 신규 사용자는 검색할 대상이 없는 경우가 많으므로, 매일 바뀌는 추천 콘텐츠로 첫 방문의 공백을 채우고 재방문 동기를 만들기 위함입니다.
- **상세 화면의 저장 버튼을 화면 하단 고정**: 정보를 끝까지 읽은 뒤 "저장할지 말지" 결정하는 것이 자연스러운 흐름이므로, 스크롤 없이 항상 접근 가능한 위치에 고정했습니다.
- **마이페이지에 "저장한 꽃"과 "최근 본 꽃"을 분리 노출**: 저장(의도적 행동)과 열람(수동적 행동)의 사용자 의도가 다르므로, 두 데이터를 하나의 리스트로 합치지 않고 구분해 재방문 시 원하는 정보에 더 빨리 도달하도록 설계했습니다.
- **검색 결과 없음 화면에서 추천 꽃 3개를 함께 노출**: 결과 없음 상태에서 이탈하지 않도록, 사용자를 다른 콘텐츠로 자연스럽게 유도하기 위함입니다 (dead-end 방지).

## #7. 이미지 후가공 방식 및 결과 문서화

**지적 사항**: 텍스트 교정·인페인팅·업스케일 등 이미지 후가공 방식 및 결과가 문서화되어 있지 않음

**보완**: 본 프로젝트는 Figma Make로 UI를 코드/컴포넌트 단위로 생성했기 때문에, 픽셀 이미지에 대한 전통적 인페인팅 대신 **컴포넌트 재생성 방식의 후가공**을 사용했습니다. 적용한 방식을 아래와 같이 정리합니다.

| 후가공 유형 | 적용 내용 | 적용 위치 |
|---|---|---|
| 텍스트 교정 | 잘리거나 겹치는 텍스트 영역을 프롬프트로 재지정하여 컴포넌트 자체를 다시 생성 (전통적 인페인팅의 코드 버전) | 상세 화면 정보 리스트, 카드 꽃 이름 라벨 |
| 레이아웃 보정 | 가로 스크롤이 발생하던 계절별 추천 칩 영역을 4열 고정 그리드로 재생성 | 메인 화면 계절별 꽃 추천 |
| 터치 영역 보정 | 44px 미만이었던 하단 탭바 아이콘 터치 영역을 확대 재생성 | 하단 네비게이션 |

## #8. 프롬프트 변경이 스타일·레이아웃·색상에 미친 영향 (사례)

**지적 사항**: 프롬프트 변경 전후의 시각적 차이를 캡처해 사례로 설명 필요

**보완**: 구체적 사례 3가지를 문서화합니다.

1. **레이아웃 영향 사례**: `수정.md`에서 "기존 디자인과 레이아웃은 유지하면서 검색 기능만 추가"라고 명시적으로 범위를 제한한 결과, 검색 기능이 실제로 동작하게 되었음에도 카드 배치·여백·컬러는 초안과 100% 동일하게 유지됨. 이는 프롬프트에서 "유지할 것"을 명시하는 것이 "바꿀 것"을 명시하는 것만큼 결과에 큰 영향을 준다는 것을 보여주는 사례입니다.
2. **색상 영향 사례**: 색상 토큰(`#F6EFDF`, `#3F5539`, `#B97A5D` 등)을 헥스 코드로 프롬프트에 직접 명시한 이후부터는 재생성을 여러 번 반복해도 색상이 매번 동일하게 유지됨. 반대로 초안 단계에서 "cream and green" 처럼 색을 서술형으로만 지시했을 때는 생성할 때마다 채도·톤이 미세하게 달라졌습니다.
3. **스타일(정체성) 영향 사례**: "herbarium / pressed-flower / ribbon bookmark" 같은 구체적 모티브 키워드를 넣기 전에는 결과물이 일반적인 파스텔톤 미니멀 앱과 구분되지 않았으나, 모티브 키워드 추가 이후 점선 테두리, 리본 태그, 테이프 장식 같은 구조적 요소가 프롬프트를 재실행할 때마다 일관되게 재생성됨.

> 📌 **실제 제출 시 추가할 것**: 위 3개 사례 각각에 대해 변경 전/후 화면을 나란히 캡처한 이미지를 `images/08_case1.png` ~ `08_case3.png`로 첨부하세요.

## #9. 왜곡 원인별 진단 및 재발 방지 절차

**지적 사항**: 왜곡 원인별 세부 진단과 재발 방지 절차(기술적 단계)가 일부 부족함

**보완**

| 왜곡 유형 | 발생 원인 진단 | 재발 방지 절차 |
|---|---|---|
| 한글 잘림 | 컨테이너 폭 대비 텍스트 길이를 고려하지 않고 고정 폭으로 생성됨 | ① 텍스트 영역에 `max-width` + `ellipsis` 규칙을 프롬프트에 명시 ② 4글자 이상 긴 꽃 이름(예: "카라향기제라늄")으로 별도 테스트 케이스를 만들어 재검증 |
| 텍스트 겹침 | 카드 내부 요소 간 여백(padding) 값이 프롬프트에 명시되지 않아 임의로 배치됨 | ① 카드 내부 패딩 수치를 프롬프트에 명시(#5 표 참고) ② 긴 텍스트가 들어갔을 때도 겹치지 않는지 확인하는 QA 스텝을 최종.md에 포함 |
| 불필요한 가로 스크롤 | 칩 버튼·아이콘의 개별 폭 합이 390px 프레임 폭을 초과 | ① 4개 칩이 화면 폭 안에 들어가도록 `flex: 1` 균등 분배 방식으로 재지정 ② 프레임 폭을 벗어나는 요소가 있는지 Figma의 Overflow 표시 기능으로 검증 |
| 잘못 연결된 화면 전환 | 유사한 이름의 화면(홈/목록/상세)이 많아 프롬프트가 지정한 대상과 다른 화면으로 연결됨 | ① 화면마다 고유 식별명을 프롬프트와 Figma 레이어명에 동일하게 사용(예: `Screen-01-Home`) ② 최종.md의 "최종 검수" 체크리스트로 전체 연결 재검증 |

## #10. 일관성 확보 전략 (시드·레퍼런스·반복 규칙)

**지적 사항**: 시드 고정(seed), 레퍼런스 사용 방식, 반복 규칙 등 일관성 확보 기술적 전략이 미기재됨

**보완**: 본 프로젝트는 Midjourney/Stable Diffusion류의 확산 모델이 아닌 **Figma Make(코드 생성형 AI)** 를 사용했기 때문에 전통적 의미의 "시드 고정"은 적용되지 않습니다. 대신 아래와 같은 대체 일관성 확보 전략을 사용했습니다.

- **디자인 토큰 고정 재사용**: `README.md`의 Color/Typography 값을 모든 프롬프트(초안·수정·최종)에 동일한 헥스 코드·서체명으로 반복 기재하여, 매 생성마다 동일한 값을 참조하도록 강제함. (시드 고정의 코드 생성 버전에 해당)
- **동일 세션 내 반복 수정**: 화면을 처음부터 다시 생성하지 않고, 같은 Figma Make 대화 세션 안에서 "기존 디자인은 유지하고 ○○만 수정"이라는 형태로 이어서 요청 — 이는 이미지 생성 AI의 "이미지-투-이미지(image reference)" 방식과 동일한 역할을 합니다.
- **컴포넌트 재사용 규칙**: 카드, 리본 태그, 버튼을 하나의 컴포넌트로 정의한 뒤 3개 화면에서 동일 컴포넌트를 인스턴스로 재사용 → 화면마다 스타일이 미세하게 달라지는 것을 원천 차단.
- **레퍼런스 이미지 사용 여부**: 별도의 외부 레퍼런스 이미지를 업로드하지 않았으며, 텍스트 프롬프트 내 모티브 키워드(압화 표본, 리본 책갈피)만으로 스타일을 지정함. (외부 레퍼런스를 사용하지 않았다는 점을 명시적으로 기록해 저작권 이슈를 사전에 차단)
